Plain-English Architecture Guide for Visitors & Judges
🏭 The 5-Stage Pipeline

Like a car assembly line, the CPU divides execution into 5 stages: IF (Fetch), ID (Decode), EX (Execute), MEM (Memory), and WB (Write-Back). At any given clock cycle, 5 different instructions are active concurrently, providing up to a ~5x throughput speedup compared to a non-pipelined core.

⚡ Hardware Forwarding (Bypassing)

When an instruction needs an operand that was computed by the preceding instruction, the CPU cannot wait for the result to travel to the register file and be read back. The Forwarding Unit detects matching register addresses and routes the result directly from the ALU or Memory output into the ALU multiplexers.

⚠️ Load-Use Hazards & Stalls

When an instruction loads data from RAM (using lw), the data is only ready at the end of the Memory stage. If the very next instruction needs that data in Execute, forwarding backward in time is physically impossible. The Hazard Detection Unit freezes Fetch & Decode and injects a 1-cycle bubble (NOP).

✂ Branch Hazards & Flushes

When a conditional branch (like beq or bne) is taken, the CPU jumps to a new target address. The two instructions speculatively fetched in IF and ID are on the wrong execution path, so the CPU flushes (clears) them by converting them to NOPs.
