🏭 The 5-Stage Pipeline

Think of a car assembly line. Instead of building one entire car from start to finish before starting the next, a 5-stage CPU divides work into 5 steps: Fetch, Decode, Execute, Memory, and Write-Back. At any given moment, 5 instructions are being processed simultaneously, giving a ~5x throughput increase.

⚡ Hardware Forwarding (Bypassing)

When instruction B needs a result that instruction A just computed, the CPU doesn't wait for instruction A to write to the register file and instruction B to read it back. Instead, dedicated Forwarding multiplexers route the result directly from the ALU or Memory output straight into the next instruction's ALU input.

⚠️ Load-Use Hazards & Stalls

When data is read from RAM (using a lw load instruction), it is only available at the end of the Memory stage. If the very next instruction immediately needs that data in the Execute stage, forwarding is physically impossible because time cannot run backward! The Hazard Detection Unit automatically pauses the Fetch & Decode stages and inserts a 1-cycle "bubble" (NOP).

✂ Branch Hazards & Flushes

When a conditional branch (like beq or bne) is taken, the CPU jumps to a new memory address. However, the CPU had already speculatively fetched the next two instructions in line. The CPU resolves the branch in the Execute stage, recognizes the jump, and flushes (discards) the two incorrectly fetched instructions by converting them into NOPs.

📊 CPI (Cycles Per Instruction)

In an ideal world with no hazards, a pipelined CPU retires 1 instruction every single clock cycle (CPI = 1.0). In real software, due to load-use stalls and branch flushes, the CPI is slightly higher. For our Bubble Sort program, it achieves a very impressive CPI of 1.46, executing 277 instructions in 404 clock cycles!
